Reap the registry's confirmed-stale entries — the leftover records of runners that died abruptly — while never touching a live run's entry

Usage: processkit-cli prune [OPTIONS]

Options:
      --error-format <format>
          How a runner-own failure is reported on stderr. `human` (the default) prints the historical `processkit-cli: <message>` prose; `json` prints exactly one bounded, versioned JSON object instead, so an adapter can branch on stable fields (`code`, `kind`, `retryable`) rather than parsing prose.
          
          Global on purpose — it is accepted before or after the subcommand, and every subcommand honors it. It never changes stdout, an exit code, or the default prose; clap's own parse-time usage errors stay human-readable in v1. See [`crate::error_envelope`] and `docs/exit-codes.md`.

          Possible values:
          - human: The historical free-text line, unchanged byte for byte
          - json:  One bounded, versioned JSON object per failed invocation (see [`crate::error_envelope`] and `fixtures/schema/cli/error.schema.json`)
          
          [default: human]

      --json
          Emit the prune tally as a single JSON object instead of a human-readable summary line. Optional, mirroring `list` — prune has a human-readable form of its own. Combines with `--dry-run`

      --dry-run
          Preview what a real prune pass would reap without deleting anything: [`crate::registry::Registry::preview_prune`] runs the exact same scan and the exact same liveness classification as a real prune, but never deletes a file — it reports the same aggregate tally a following real prune would produce, plus the confirmed-stale candidates it would reap. Combines with `--json`

      --label <KEY=VALUE>
          Restrict paired registry entries to runs carrying every `KEY=VALUE` label. Repeatable; filters combine with logical AND. An explicit filter leaves record-less orphan locks alone because their ownership cannot be established

  -h, --help
          Print help (see a summary with '-h')
